# تحليل مشروع EMAA

## الفكرة

EMAA منصة ويب تعليمية تساعد الطالب الأصم أو ضعيف النطق على التواصل الفوري مع المعلم أو موظف الدعم الأكاديمي. يعتمد النظام على عدة وكلاء برمجيين: وكيل للرؤية، وكيل لاستخراج النية، وكيل لصياغة الرسالة، وكيل لتبسيط المصطلحات، ووكيل لتحليل النبرة.

## المستخدمون

- الطالب: يبدأ الجلسة، يستخدم الكاميرا أو الرسائل السريعة، ويرى رد الطرف الآخر كنص واضح مع مؤشر نبرة.
- المعلم أو الدعم: يستقبل رسالة الطالب كنص وصوت، ثم يرد نصياً أو صوتياً.
- المدير: يدير الإشارات والمصطلحات والمستخدمين ويراقب المؤشرات.

## المتطلبات المحولة إلى التطبيق

- بدء وإنهاء جلسة تواصل.
- تشغيل الكاميرا والمايكروفون بعد إذن المستخدم.
- تحليل إشارة تعليمية إلى نية.
- عرض نسبة الثقة وطلب التأكيد عند انخفاضها.
- تحويل النية إلى نص عربي أو إنجليزي.
- تدريب أولي للإشارات من الكاميرا باستخدام MediaPipe Hand Landmarker وعينات محفوظة محلياً، ثم بناء نموذج محلي يعتمد على متوسط معالم كل إشارة.
- تشغيل رسالة الطالب صوتياً عبر Web Speech Synthesis.
- استقبال رد المعلم نصياً أو عبر Web Speech Recognition عند توفره في المتصفح.
- تبسيط المصطلحات الأكاديمية الموجودة في الرد.
- تحليل النبرة وعرضها للطالب.
- حفظ سجل المحادثة محلياً.
- إدارة المصطلحات والإشارات من لوحة المدير.

## حدود النسخة الحالية

هذه نسخة MVP تشغيلية للعرض والتجربة. أضيف لها تعرف أولي يعتمد على حفظ عينات من معالم اليد، تدريب نموذج محلي لكل إشارة، ثم المقارنة مع النموذج المدرب. هذا مناسب للعرض وإثبات الفكرة، لكنه ليس بديلاً عن نموذج رؤية حاسوبية مدرب على Dataset واسع ومراجع من مختصين بلغة الإشارة.

## التوسعة التالية

- إضافة Backend باستخدام FastAPI أو Node.js.
- ربط WebSocket لجلسات مباشرة بين جهاز الطالب وجهاز المعلم.
- تدريب نموذج MediaPipe + Classifier للإشارات العشرين الأولى.
- إضافة تسجيل دخول وصلاحيات.
- نقل البيانات من `localStorage` إلى PostgreSQL أو Supabase.
- حفظ سجلات الجلسات مع سياسة خصوصية تمنع تخزين الفيديو الخام.
